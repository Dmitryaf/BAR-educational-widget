# Модель обучения

Обновлено: 2026-08-01.

## Основная идея

Новичку сначала нужен небольшой воспроизводимый практический каркас. Понимание экономики формируется через повторение связанного opening и короткое объяснение причины, когда выполнение останавливается.

```text
следующий наблюдаемый результат
→ самостоятельное действие игрока
→ подтверждение результата
→ следующий результат
```

## Единица обучения

Единица обучения — milestone, а не вопрос и не отдельная ошибка.

Milestone описывает:

- наблюдаемый результат;
- короткую рекомендацию;
- минимальные evidence для завершения;
- допустимые альтернативы;
- причины `unknown`;
- recovery, способный временно остановить продвижение.

## Состояния milestone

- `not_started` — достаточные данные есть, признаки выполнения отсутствуют;
- `in_progress` — часть результата уже наблюдается;
- `complete` — критерии результата подтверждены;
- `skipped_validly` — игрок достиг эквивалентного результата допустимым способом;
- `blocked` — подтверждённая проблема сейчас мешает шагу;
- `unknown` — данных недостаточно для вывода.

`unknown` нельзя преобразовывать в `not_started` или ошибку игрока.

## Порядок без жёсткого сценария

Milestones упорядочены для показа ближайшего шага, но игрок может выполнить более поздний результат раньше. Достигнутый milestone запоминается в текущей team/context/game timeline даже после последующей потери unit: он описывает уже пройденный учебный результат, а не текущую боеспособность. Текущий регресс сохраняется отдельно как `observedState`; советы по восстановлению после атаки не относятся к opening lesson. Память очищается при explicit reset, смене team/context или rewind.

Точный build order, секунды и идеальное число buildings не являются целью. Настраиваемые пороги нужны только для достаточно ясного первого lesson и подлежат runtime validation.

## Replay как evidence, а не скрипт

Реплеи сильных игроков нужны, чтобы проверить сам выбор opening, найти повторяющиеся промежуточные результаты и увидеть допустимые ветки. Одна игра не образует lesson.

Анализ должен:

- заранее фиксировать выборку, не отбирая только удобные игры;
- искать ranges и общие инварианты, а не fastest timing;
- отделять стабильный opening от matchup/scouting-адаптации;
- не использовать скрытые данные о противнике в recommendation logic;
- добавлять beginner margin только как гипотезу с последующей ручной и usefulness validation.

Совпадение с top-player timing не является критерием усвоения.

Реплеи проверяют содержание lesson, но не метод обучения. Они не показывают, успевает ли новичок читать карточку, понимает ли действие и сохраняется ли навык без виджета.

## Recovery

Recovery не образует самостоятельную программу обучения. Подтверждённый `ENERGY_STALL` временно заменяет milestone-card, потому что без энергии выбранное действие может быть бессмысленным или выполняться слишком медленно.

После устойчивого восстановления виджет возвращается к первому незавершённому milestone. Неподтверждённые причины, включая нехватку metal или build power, остаются debug evidence и не превращаются в уверенную пользовательскую рекомендацию.

## Снижение помощи

Практическая проверка должна сравнивать:

1. выполнение того же lesson со статической шпаргалкой;
2. выполнение lesson с полными live-подсказками;
3. повторение с более редкими подсказками;
4. повторение без виджета и шпаргалки.

На небольшой выборке это качественный продуктовый тест, а не статистическое доказательство. Нужно фиксировать наблюдаемое выполнение, случаи непонимания, отвлечение карточкой и субъективное желание пройти ещё один lesson.

Автоматическое усложнение или скрытая оценка в MVP не нужны. Снижение помощи можно проводить вручную во время validation.

## Качество текста

Во время матча текст должен быть коротким и прямым:

- без рефлексивных вопросов;
- без требования клика;
- без обвиняющих формулировок;
- без длинного объяснения механики;
- без конкретного unit, если context и build options не подтверждены;
- без обещания, что один шаг всегда стратегически оптимален.

## Что считается усвоением

Усвоение — способность самостоятельно воспроизвести причинную цепочку opening, а не запомнить карточки дословно. Если игрок умеет начать доход, запустить factory, поддержать производство, расшириться и сохранить армию без виджета, lesson выполнил задачу.
